## Context

PLAN.md item 04 says "Making the app a PWM" — read as **PWA** (recorded here; a
pomodoro tracker has no plausible pulse-width-modulation reading). The product
is tablet-first: it should live on the home screen and launch full-screen
without browser chrome. Per product decision, that is the *entire* requirement
— **installable, explicitly not offline**.

Installability criteria verified against web.dev on 2026-07-23: HTTPS + a
manifest with `name`/`short_name`, **192 px and 512 px icons**, `start_url`,
and a standalone-class `display` — **no service worker and no offline
capability required**. That makes this ADR small: a manifest, a proper icon
set, and Apple metadata.

The repo carries the GLU mark at `img/favicon.svg` (source of truth;
`img/favicon.png` is a **508×523 non-square** export). ADR 01 (as amended)
wires the browser-tab favicon; this ADR owns the installable icon set, which
has hard squareness and safe-zone requirements the current assets don't meet
as-is.

**Prerequisites: ADRs 01 and 02 Implemented** (there must be an app worth
installing; the basePath and favicon wiring come from 01). ADR 03 is no longer
a blocking prerequisite — with no service worker there is no caching layer to
guard with tests.

## Decision

- **We will ship no service worker at all.** The product declined offline; an
  SW's only remaining jobs here would be caching and update management — pure
  debugging surface with zero requirement behind it. Consequence accepted and
  recorded: with no network, an **already-open** app keeps running (the timer
  needs no network), but a **reload** shows the browser's offline error page;
  localStorage state is untouched and the app resumes correctly once back
  online. If that ever bites → future **ADR: offline mode**.
- **We will define the manifest via `app/manifest.ts`** (typed, and the link
  tag the convention emits gets the basePath). `name`/`short_name` "GLU",
  `display: "standalone"`, `id`/`start_url`/`scope` under `/glu/`, **no
  orientation lock** — half-tablet portrait use is a first-class mode.
  `theme_color: "#141D2A"` (the mark's ink), `background_color: "#ffffff"` —
  placeholders; ADR 08 will make the site's colors clock-driven and may amend.
- **We will generate the full icon set from `img/favicon.svg` — never from the
  PNG.** The PNG is non-square; scaling it into square slots distorts or crops.
  A one-shot committed script (`scripts/generate-icons.mjs`, sharp) renders:
  192 and 512 standard, 512 **maskable** (content padded into the safe zone),
  and 180 apple-touch-icon with a **solid light background** — iOS composites
  transparency as black. Outputs are committed; the script reruns manually when
  the mark changes. Build-time icon generation is a dependency tax for assets
  that change roughly never.
- **We will not ship sounds or notifications in this ADR.** ADR 02 deferred
  session-end alerts "to ADR 04+"; alerting from a closed/installed app is
  Push API territory — its own can of worms → named future **ADR: session-end
  alerts**.

## Options considered

- **First draft of this ADR (Serwist service worker, app-shell precache,
  auto-update, offline)** — reversed by product decision the same day:
  installability is the requirement, offline is not. Rejected; the research
  (Serwist 9.5.12, dedicated Turbopack setup path) is preserved below for a
  future offline ADR.
- **A minimal "empty" service worker anyway** — buys nothing the install
  criteria need, costs the full SW debugging surface (stale registrations,
  update lifecycle) the product just declined. Rejected.
- **`next-pwa` / Serwist / hand-rolled SW comparisons** — moot with no service
  worker in scope.
- **Build-time icon generation** — adds sharp to every build for assets that
  change never. Rejected for a committed one-shot script.
- **Orientation lock (landscape)** — kills the half-tablet mode PLAN.md calls
  out. Rejected.

## Scope

### In scope

- `app/manifest.ts` with correct `/glu/` `id`/`start_url`/`scope` and the
  icon entries Chrome's install criteria require (192 + 512).
- Icon generation script + committed outputs (192, 512, 512-maskable,
  180 apple-touch) from `img/favicon.svg`; apple-touch/`appleWebApp` metadata
  and dark/light `theme-color` via the viewport export.
- Install verification on the two real targets (Android tablet Chrome, iPad
  Safari) or their emulations, including verifying **no** service worker is
  registered.
- README: short install-to-home-screen note.

### Out of scope

- **Any service worker, offline support, caching, or update flow** → future
  **ADR: offline mode** if ever wanted. For that ADR: first-draft research
  found Serwist 9.5.12 the maintained choice, with a dedicated Turbopack setup
  guide (`next-pwa` is stale at 5.6.0).
- Session-end sound/notifications → materialized as **ADR 18** (chime +
  page-context Notification, no service worker; its Android-notification
  escalation would require amending this ADR's no-SW constraint first).
- Screen wake lock while a timer runs → future **ADR: wake lock**.
- Backend and `/api` → materialized as **ADR 11** (stateless Todoist proxy —
  its permanent scope; the sync half was cancelled 2026-07-24). (The first
  draft's standing rule — amend SW caching before any `/api` fetch —
  dissolved with the service worker; nothing to amend.)
- Push, background sync, periodic sync — no SW, nothing to attach them to.
- Todoist area → its future ADR.

## Implementation outline

1. **Icon script** (`scripts/generate-icons.mjs`, sharp as a devDependency):
   render the SVG onto square canvases → `public/icons/` for the manifest's
   entries, and → `src/app/` for the two file-convention icons
   (`icon.png`, `apple-icon.png`). **Gotcha:** the SVG
   viewBox is 508×523 — center it on the square, don't stretch. **Gotcha:**
   maskable safe zone is a centered circle of 40% radius; scale the mark to
   ~66% of the canvas with an opaque background, then sanity-check on
   maskable.app — a full-bleed glyph gets its edges eaten by round Android
   masks. Apple-touch gets a solid light background (`#f5f6f8`).
2. **`app/manifest.ts`** — fields per the Decision. **Gotcha:** the manifest
   *link* gets the basePath from the file convention, but URLs *inside* the
   manifest don't; use paths relative to the manifest (`icons/icon-192.png`) so
   they resolve under `/glu/` by spec instead of hardcoding the prefix.
3. **Layout metadata** — `appleWebApp` (title, capable) in `metadata`;
   `themeColor` with dark/light media variants goes in the **`viewport`
   export** — Next warns-and-ignores it under `metadata` since v14, a classic
   silent-miss. **Gotcha (2026-07-25 amendment):** do *not* add an `icons` key
   to `metadata` — it replaces the whole file-convention icon set rather than
   adding to it, and its URLs skip the basePath. Icons ship as files.
4. **Verify on prod build** (`next build && next start`): devtools Application
   panel — manifest checks green **and the Service Workers pane empty**;
   install on both targets (iPad has no install prompt — Share → Add to Home
   Screen is the only path); launch standalone; cut the network on an
   already-open app and confirm the timer keeps running; reload offline and
   confirm the browser error page is the (accepted) behavior, with state
   intact after reconnecting.
5. **README install note** — three lines, both platforms.

Honest sizing: **half a day to a day**. The icon safe-zone fiddling and the
two-device verification pass are all of it; there is no moving part left.

## Consequences

- The app becomes a home-screen, full-screen tool with **zero** new runtime
  machinery — no service worker means no cache debugging, no update lifecycle,
  no stale-shell class of bugs, ever, until an offline ADR deliberately buys
  them back.
- Offline is a known non-feature, recorded: a reload on dead wifi is a browser
  error page. The timer's localStorage/`endAt` design (ADR 02) means nothing
  is lost — the session picks up correctly on reconnect.
- The backend (ADR 11's proxy) got simpler: no SW caching strategy to amend
  before its first `/api` call.
- The icon pipeline gives any future visual-identity ADR one file to change
  (`img/favicon.svg`) and one script to rerun.
- If offline is ever requested, it is an additive ADR (manifest and icons
  stay; a service worker joins) — nothing in this ADR gets undone.
